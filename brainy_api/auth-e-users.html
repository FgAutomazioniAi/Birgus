Accedi (login) ​

POST/brainy/api/authpubblico

Autentica un utente con login e password e apre una sessione.

Per i client browser la risposta imposta un cookie brainy_token (HttpOnly, 8 ore) e il token NON è incluso nel corpo. Per i client API/service usa invece POST /api/auth/service, che restituisce il token nel corpo.

Casi particolari:

  • Primo accesso / password resettata (must_change_password=1): il cookie NON viene impostato e il token è restituito nel corpo, da usare come Bearer per la sola chiamata di cambio password (POST /api/auth/users/me).
  • Login di dominio `DOMINIO\utente`: se Active Directory è attivo le credenziali sono verificate sul Domain Controller (nessun fallback locale).
  • Blocco account: dopo 5 tentativi falliti l'account è bloccato per 15 minuti (HTTP 423). Un admin può sbloccarlo con unlock.

Autorizzazione — Nessun controllo di auth rilevato. Vedi Autenticazione.

Corpo della richiesta ​

ParametroTipoDescrizione
loginbodyUsername locale, oppure `DOMINIO\utente` per un account Active Directory.
secretbodyPassword in chiaro. Viaggia solo su TLS ed è confrontata come hash lato server.

Esempi ​

Richiesta

bash
curl -s -c cookies.txt "$BRAINY_BASE/brainy/api/auth" \
  -H "Content-Type: application/json" \
  -d '{"login":"mario","secret":"S3gr3ta!"}'

Risposta (login normale, il token è nel cookie brainy_token)

json
{
  "id": 42,
  "login": "mario",
  "name": "Mario Rossi",
  "admin": 0,
  "profile": "USER",
  "active": 1,
  "thumbnail": "thumb.png",
  "must_change_password": 0
}

Accedi come account di servizio ​

POST/brainy/api/auth/servicepubblico

Autentica un account di servizio tramite Access Key e Secret Key e restituisce il token nel corpo (i client non-browser non usano il cookie). Pensato per integrazioni server-to-server: il token va poi inviato come Authorization: Bearer. Le chiavi si generano e gestiscono dalla sezione «Account di servizio» di Utenti e Gruppi.

Autorizzazione — Nessun controllo di auth rilevato. Vedi Autenticazione.

Corpo della richiesta ​

ParametroTipoDescrizione

secret_keybodySegreto associato, mostrato una sola volta alla creazione.

Esempi ​

Richiesta

curl -s "$BRAINY_BASE/brainy/api/auth/service" \
  -H "Content-Type: application/json" \

Sessione corrente (whoami) ​

GET/brainy/api/authautenticato

Restituisce l'identità associata al token della richiesta: profilo USER o SERVICE, livello admin, organizzazione e gruppi di appartenenza. È il modo canonico per verificare che una sessione sia valida e per popolare lo stato utente del frontend all'avvio.

Autorizzazione — Bearer token (qualsiasi utente autenticato). Vedi Autenticazione.

Crea o aggiorna un utente ​

POST/brainy/api/auth/usersadmin / group-admin

Crea un nuovo utente (senza id nel corpo) o ne aggiorna uno esistente (con id). Riservato agli admin e, in ambito limitato, agli amministratori di gruppo (che possono agire solo sui propri gruppi e non assegnare privilegi admin).

Alla creazione, la password fornita è considerata iniziale: l'utente sarà obbligato a cambiarla al primo accesso. Le password devono rispettare la policy: in caso contrario la risposta è 422 con l'elenco dei requisiti non soddisfatti. Restituisce l'id dell'utente.

Autorizzazione — Admin, oppure amministratore di gruppo limitatamente ai propri gruppi (non può assegnare privilegi admin). Vedi Autenticazione.

Corpo della richiesta ​

ParametroTipoDescrizione
idbodyID dell'utente da aggiornare. Assente = creazione.
loginbodyUsername (univoco nell'organizzazione).
namebodyNome visualizzato.
adminbodyLivello amministrativo (0 = utente normale). Ignorato per gli amministratori di gruppo.
activebodySe false, l'utente non può accedere. Default true.
thumbnailbodyImmagine profilo come data-URI o nome file; null per rimuoverla.
groupsbodyElenco di gruppi (ciascuno con id e group_admin) a cui assegnare l'utente; sostituisce quelli esistenti.
profilebodyTipo dell’account, USER (default) o SERVICE.
secretbodyPassword iniziale in chiaro. Deve rispettare la policy.
section_permissionsbodyda documentare

Errori ​

CodiceCondizione

403Forbidden
409Login already taken

Aggiorna il proprio profilo / cambia password ​

POST/brainy/api/auth/users/meautenticato

Aggiornamento self-service del proprio account: nome, immagine profilo e/o password. Aggiorna solo i campi presenti nel corpo (update parziale).

Per cambiare la password serve la password attuale (current_secret), a protezione da furto di sessione — tranne quando l'utente sta completando un cambio forzato (must_change_password=1). La nuova password deve rispettare la policy (422 altrimenti). Al cambio, i token precedenti sono invalidati e viene emesso un nuovo cookie/X-Refresh-Token così la sessione resta attiva.

Autorizzazione — Bearer token (qualsiasi utente autenticato). Vedi Autenticazione.

Corpo della richiesta ​

ParametroTipoDescrizione
namebodyNuovo nome visualizzato.
thumbnailbodyNuova immagine profilo (data-URI/nome file); null per rimuoverla.
secretbodyNuova password in chiaro (opzionale).
current_secretbodyPassword attuale, richiesta quando si cambia secret (salvo cambio forzato).

Errori ​

CodiceCondizione
400No fields to update
401Password attuale errata.
403Forbidden
422Per cambiare password serve la password attuale.

Esempi ​

Richiesta (cambio password)

bash
curl -s "$BRAINY_BASE/brainy/api/auth/users/me" -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"secret":"NuovaPsw1!","current_secret":"S3gr3ta!"}'
