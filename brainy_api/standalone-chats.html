Standalone Chats ​

17 endpoint.

Elenco chatbot ​

GET/brainy/api/standalone-chatsautenticato

Lista paginata dei chatbot visibili al chiamante, con filtro per nome e ordinamento. Ogni riga include agente, modalità di accesso, token pubblico, stato e numero di condivisioni.

Autorizzazione — Autenticato; gli admin vedono tutto, gli altri le chat proprie o condivise. Vedi Autenticazione.

Parametri di query ​

ParametroTipoDescrizione
load_cursorqueryOffset di paginazione. Default 0.
page_sizequeryVoci per pagina. Default 100.
namequeryFiltro per sottostringa sul nome.
order_byqueryOrdinamento (name, agent, access, status).
order_dirqueryDirezione (asc/desc).

Esempi ​

Richiesta

bash
curl -s "$BRAINY_BASE/brainy/api/standalone-chats" -H "Authorization: Bearer $TOKEN"

Dettaglio chatbot ​

GET/brainy/api/standalone-chats/{id}autenticato

Restituisce la configurazione completa di un chatbot (branding, skin, header, prompt suggeriti, template, modalità di accesso, token pubblico).

Autorizzazione — Autenticato con almeno ruolo EXEC sulla chat (propria, condivisa o admin). Vedi Autenticazione.

Parametri di path ​

ParametroTipoDescrizione
idpathID del chatbot.

Crea o sostituisci un chatbot ​

POST/brainy/api/standalone-chatsautenticato

Crea un chatbot (senza id) o lo sostituisce integralmente (con id). Alla creazione viene coniato il token pubblico tk_...; se auth_mode è public, viene garantito anche il token pubblico dell'agente sottostante.

Autorizzazione — Creazione — qualsiasi autenticato. Aggiornamento (con id) — ruolo EDIT sulla chat. Vedi Autenticazione.

Corpo della richiesta ​

ParametroTipoDescrizione
idbodyID del chatbot da aggiornare (assente = creazione).
agent_idbodyID dell'agente avvolto dal chatbot (obbligatorio).
namebodyNome del chatbot (obbligatorio).
auth_modebodyModalità di accesso, public (default) o login.
icon_databodyIcona come base64 (legacy; preferire icon_key).
header_logo_databodyLogo header come base64 (legacy; preferire header_logo_key).
icon_keybodyChiave S3 dell'icona (da upload).
header_logo_keybodyChiave S3 del logo dell'header (da upload).
titlebodyTitolo mostrato nella pagina.
welcome_messagebodyMessaggio di benvenuto.
placeholderbodyTesto segnaposto del campo di input.
skin_template_idbodyID della skin da applicare.
header_enabledbodySe true, mostra l'header.
header_titlebodyTitolo mostrato nell'header.
header_subtitlebodySottotitolo dell'header.
suggested_promptsbodyPrompt suggeriti (array o stringa JSON).
show_historybodySe 1, mostra lo storico delle conversazioni.
params_specbodySpecifica dei parametri URL dichiarati.
persist_sessionbodySe 1, mantiene la sessione tra le visite. Default 1.
enabledbodySe true, il chatbot è attivo/pubblicato.

Esempi ​

Richiesta (creazione)

bash
curl -s -X POST "$BRAINY_BASE/brainy/api/standalone-chats" \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"agent_id":28,"name":"Assistente Sito","auth_mode":"public"}'

Imposta le condivisioni di un chatbot ​

POST/brainy/api/standalone-chats/shares/{id}autenticato

Sostituisce integralmente le condivisioni. I ruoli sono 1 (EXEC, solo uso), 2 (EDIT, uso e modifica), 3 (OWNER). Il proprietario resta invariato.

Autorizzazione — Autenticato, proprietario del chatbot (ruolo OWNER) o admin. Vedi Autenticazione.

Parametri di path ​

ParametroTipoDescrizione
idpathID del chatbot.

Corpo della richiesta ​

ParametroTipoDescrizione
permissionsbodyElenco di voci con id (utente/gruppo) e role (1/2/3).

Errori ​

CodiceCondizione
400ruolo non ammesso: ${p?.role}

Esempi ​

Richiesta

bash
curl -s -X POST "$BRAINY_BASE/brainy/api/standalone-chats/shares/204" \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"permissions":[{"id":7,"role":1}]}'

Config della pagina pubblica (widget) ​

GET/brainy/api/ai/public/chat-app/{tk}pubblico

Endpoint pubblico della pagina chatbot: dato il token tk_... della chat, restituisce tutta la config di rendering (agente, titolo, skin risolta, header, prompt suggeriti, parametri dichiarati). In modalità public include anche la publishable key dell'agente; in modalità login è omessa. Token inesistente → 404; chat disabilitata → 403.

Autorizzazione — Pubblico — il token della chat (tk_...) è l'autorizzazione; nessun login. Vedi Autenticazione.

Parametri di path ​

ParametroTipoDescrizione
tkpathToken pubblico della chat (formato tk_ + 32 hex).

Errori ​

CodiceCondizione
403Chat disabled
404Not found

Esempi ​

Richiesta

bash
curl -s "$BRAINY_BASE/brainy/api/ai/public/chat-app/tk_xxxxxxxx"

Esporta l'output in docx/pdf (pubblico) ​

POST/brainy/api/ai/public/chat-app/{tk}/export-docxpubblico

Endpoint pubblico: rende il markdown fornito nel template docx della chat e restituisce il file (docx di default, oppure pdf). Solo i parametri dichiarati nella chat vengono usati. Token non valido/chat disattivata → 404; markdown mancante → 400.

Autorizzazione — Pubblico — il token della chat (tk_...) è l'autorizzazione; nessun login. Vedi Autenticazione.

Parametri di path ​

ParametroTipoDescrizione
tkpathToken pubblico della chat (formato tk_ + 32 hex).

Corpo della richiesta ​

ParametroTipoDescrizione
markdownbodyContenuto markdown da rendere (obbligatorio).
paramsbodyValori dei parametri dichiarati dalla chat.
varsbodyValori asseriti dall'agente (val_*) usati nel template.
titlebodyTitolo del documento / nome file (max 200 caratteri).
formatbodyFormato di output, docx (default) o pdf.

Errori ​

CodiceCondizione
400markdown mancante
404Not found

Esempi ​

Richiesta

bash
curl -s -X POST "$BRAINY_BASE/brainy/api/ai/public/chat-app/tk_xxxxxxxx/export-docx" \
  -H "Content-Type: application/json" \
  -d '{"markdown":"# Report\nTesto…","title":"Report","format":"docx"}' --output report.docx
