Database Connections ​

27 endpoint.

Provider supportati ​

GET/brainy/api/database/connections/providersadmin

Elenca i tipi di database supportati (per il form di creazione).

Autorizzazione — Solo amministratori. Vedi Autenticazione.

Elenco connessioni ​

GET/brainy/api/database/connectionsautenticato

Lista delle connessioni visibili al chiamante, con lo stato di training. Le password non sono mai restituite (solo has_password).

Autorizzazione — Autenticato; gli admin vedono tutte, gli altri quelle su cui hanno permesso (ACL). Vedi Autenticazione.

Esempi ​

Richiesta

bash
curl -s "$BRAINY_BASE/brainy/api/database/connections" -H "Authorization: Bearer $TOKEN"

Crea una connessione ​

POST/brainy/api/database/connectionsadmin

Crea una connessione a un database esterno e avvia il training asincrono (parsing dello schema + generazione del prompt). Le credenziali vengono cifrate. Il creatore diventa proprietario (OWNER).

Autorizzazione — Solo amministratori. Vedi Autenticazione.

Corpo della richiesta ​

ParametroTipoDescrizione
db_typebodyTipo di database (mysql, postgresql, mssql, oracle).
passwordbodyPassword (cifrata a riposo).
namebodyNome della connessione.
hostbodyHost del database.
portbodyPorta.
databasebodyNome del database/schema.
usernamebodyUtente.
access_modebodyModalità READ_ONLY (default) oppure READ_WRITE.
allow_ddlbodySe true, consente istruzioni DDL (solo con READ_WRITE).

Esempi ​

Richiesta

bash
curl -s -X POST "$BRAINY_BASE/brainy/api/database/connections" \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"db_type":"mysql","name":"Employees","host":"db.example","port":3306,"database":"employees","username":"ro","password":"…"}'

Query SQL grezza ​

POST/brainy/api/database/connections/{id}/query/rawautenticato

Esegue SQL grezzo contro il database esterno. Attenzione: su una connessione READ_WRITE (con allow_ddl) può modificare i dati esterni. La protezione dalle scritture dipende interamente dalla access_mode della connessione; a livello L2 basta il permesso di lettura. Le scritture che richiedono conferma tornano 400 con needsConfirm. Ogni query è tracciata (audit).

Autorizzazione — Autenticato con permesso di lettura sulla connessione (ACL READ); la scrittura dipende dalla modalità della connessione. Vedi Autenticazione.

Parametri di path ​

ParametroTipoDescrizione
idpathID della connessione.

Corpo della richiesta ​

ParametroTipoDescrizione
sqlbodyIstruzione SQL da eseguire.

Esempi ​

Richiesta

bash
curl -s -X POST "$BRAINY_BASE/brainy/api/database/connections/2/query/raw" \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"sql":"SELECT * FROM departments LIMIT 10"}'

Autorizzazione — Autenticato con permesso di lettura sulla connessione (ACL READ). Vedi Autenticazione.

session_idbodyID della sessione (assente = nuova).
session_namebodyNome della sessione (default dalle prime parole del messaggio).
